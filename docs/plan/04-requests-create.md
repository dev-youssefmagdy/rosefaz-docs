# Phase 04 — Requests: schema, list, create (read 00-overview.md first; phases 01–03 done)
1. Migrations + models `ContractRequest`, `RequestNote` (note model: `UPDATED_AT = null`, throw `LogicException` in `updating`/`deleting` events). Factories. `ContractRequest` accessors `birth_date_hijri`, `start_date_hijri`, scopes `forUser($user)` (BM → own branch only; GM → all). Casts for dates/decimals/bool/enums.
2. `ref_no` generated in `ContractRequestService::create()` inside DB transaction with lock (max id per year +1). Service also computes `remaining_amount`, forces `branch_id` = BM's branch, `created_by`, `request_date = today`. Verify `employee_id` is active and belongs to that branch or is global.
3. Policy `ContractRequestPolicy`: viewAny (both roles), view (GM any; BM same branch), create (BM only), update/delete **always false**. GM cannot create requests.
4. `StoreContractRequestRequest`: rules per overview (id_number `digits:10`, mobile regex, dates, decimals ≥0, amount_paid ≤ annual_rent, rental_type enum, duration 1–600, employee exists). Arabic messages.
5. Routes: `GET /requests` (list page), `GET /requests/list?q=&branch_id=&page=` (JSON; GM sees all with unread flag, BM only own), `GET /requests/create` (BM only), `POST /requests` (JSON → `{id, url}`), then redirect client to show page.
